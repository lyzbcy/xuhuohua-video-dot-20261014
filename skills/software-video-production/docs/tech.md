# 工具与重建经验

现状：本地剪辑已验证；案例脚本是素材专用原型。
维护人：当前制作 Agent。
最后更新：2026-10-14。

## 已用工具

- FFmpeg/ffprobe：探测、旋转、HDR、编码、裁切、解码与响度。
- Python/Pillow/Numpy：图形、字幕、器乐合成和时间轴。
- OpenCV/RapidOCR：光流与文字检测遮罩，不代替隐私检查。
- edge-tts：中文配音与语音边界，服务与版本可用性要实时核实。

工具不是唯一方案，也不证明最终质感。合适的剪辑软件、Canvas 或生成媒体能力可以选用。

## 本次源媒体

32.315 秒，1920×1080 HEVC Main 10，带 -90° 旋转矩阵，实际竖屏，HLG/BT.2020。仅看编码尺寸会误认方向，忽略色彩信息可能发灰或过曝。

本次一版色调映射明显洗白，换参数后抽查解码帧修正。`hable:peak=10` 是该素材选择，不是通用 HDR 预设。新片先选代表帧比较再转整片。

## 脚本边界

`LOCAL_ONLY_SOURCE`、`render_v2.py` 包含固定区间、四边形、画布、配色和路径。

可研究遮罩、时间戳和音频处理；不得搬坐标到新视频，也不按同版式默认生产。用户已指出其像 PPT。v3 为精确裁切 v2 去掉 1 秒片头，以实际文件为准，旧脚本不一定直接重建最终修订。

## 具体陷阱

- 原片是 `_raw.mp4`，提示曾为 `_raw\.mp4`，先查明确父目录。
- 长 Python/过滤器表达式在 PowerShell 双引号易被误解析；保存脚本、参数列表或过滤器文件。
- 复制脚本后检查输出目录，避免仍写到上一版位置。
- 素材、遮罩、语音与字幕缓存对应配置；改文案不能只换显示文字。
- 增减片头要检查绝对时间；裁切后仍核对音乐与事件音效。
- 缺帧/跟踪失效不能默默用最近帧冒充连续实拍；冻结是剪辑选择，需知道位置和用途。
- 抽帧编号不一定是精确源时间；核对帧时间戳、采样偏移与帧率。
- Chromium/Electron中4K截图不代表录屏也为4K。一次DPI覆写下截图3840×2160，但screencast仍1920×1080；正式录像改用实际窗口与渲染缩放后每帧核尺寸。软件zoom和设备模拟DPR同时放大也可能让布局变窄、标题横向裁切：像素尺寸通过后仍看实际构图，局部视图先恢复zoom，再设置目标viewport。录制截图与screencast并发可能停滞，用已收录的帧另存审阅图，避免另发截图抢占；不把低清记录放大冒充原生。具体可运行例留一键投递项目。
- edge-tts可用合成词边界对齐实际文案；每段MP3可能多留约0.6秒尾静音。按真实末词加适当尾音余量裁切，避免多段拼接形成叙事空洞；不是机械裁所有停顿。改讲解后重新生成音频、词边界、字幕及界面入出点。

## 可重复工具

[media_check.py](../scripts/media_check.py) 负责探测/验证，不承载视觉模板。换机器先查 FFmpeg、ffprobe、Python。

重建资料记录原片、源时间、文案/音色、素材与音乐来源、遮罩与导出；最终只有裁切命令也登记源版本和入点。
