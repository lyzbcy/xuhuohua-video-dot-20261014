# 留人、自由创意与去 PPT 感

现状：已识别首例弱点；新表达待后续作品验证。
维护人：当前制作 Agent。
最后更新：2026-10-15。

## 问题是什么

桌脚看电视片可说明功能、引导获取，但用户认为“有点像一个ppt或者说html ppt”“劣质感比较足”。加标题动画、卡片移动、RGB 转场，没有自动改变整条片的表达形态。

下一次要改画面如何讲故事，不能只增加动画数量或放大模型署名。

## 开场

第一帧和第一句话给继续看的理由：反常结果、熟悉场景里的异常、立即发生的变化、明确的问题。观众先想知道发生了什么，再理解产品名。

先比较原片里最强的真人/操作瞬间和拟新做的片头。用户对一键投递v3说“不错不错”，但认为卡片开头是全片最弱画面，建议把后面劲爆内容前置。此系列可优先试正文精彩片段的冷开场，再回接原因和演示；前置引用保留事实与语境，不把最弱的图形画面放在最需要留人的位置。这不是禁止所有原创片头，具体见[案例](cases/2026-10-15-one-click.md)。

软件演示同时要让观众在前段知道产品如何回应这个问题。一次看懂的操作应有对象、动作、反馈；需要讲解而原片缺少时，可在授权范围内补通用配音。[一键投递60分返工](cases/2026-10-15-one-click.md)说明：保留长音乐画面、删去不匹配歌词，并没有补上解释缺口。不能把私人日常认可的音乐/RPG时长直接套到对客演示。

本次直接“你以为这是广告？”加真实小窗比独立署名片头好。署名作为次要层级放在钩子画面上方。此句不是每条视频的固定开场，新素材要找新的视觉钩子。

## 自由创意空间

先选与产品能力有关的构想，再让它贯穿画面和声音；按素材自由组合，不必凑齐类型。

| 方向 | 可尝试的表达 | 功能证据如何保留 |
| --- | --- | --- |
| 微情境/反应 | 目光、手部动作、脚步、误会和反转 | 关键动作与结果接回真实操作 |
| 空间隐喻 | 小电视“住进”屏幕角落，元素穿过画面边缘 | 示意与真实 UI 保持视觉区分 |
| 镜头语言 | 视线引导、匹配剪辑、遮挡转场、构图/景别变化 | 源时间能解释操作先后 |
| 节奏演示 | 动作、变化、反应由拍点串起，短停顿制造惊讶 | 关键变化留到能看懂 |
| 原创视觉插入 | 原创小角色、插画或短生成镜头承担情绪/笑点 | 不生成冒充真实软件的演示 |
| 原创音乐/歌曲 | 用产品动作/剧情反转做音乐动机，条件具备时试带唱 | 歌词不新增未经证实功能 |

这些是**待探索方向**，不是已经实片验证的优秀 SOP。生成能力、费用与授权以当前环境为准；没有相应工具就换已有手段，不宣称完成生成。

## 判断运动是否有用

需要具体例子先读[范例选择](exemplars.md)，再看[ED01](../examples/cards/ED01.md)的字/实物/真人切换、[MG01](../examples/cards/MG01.md)的操作聚焦、[MG02](../examples/cards/MG02.md)的编辑反馈、[MV01](../examples/cards/MV01.md)的语义动作。按本片问题选取，不把几套风格全部叠加。片段有源秒数和审阅范围；普通字幕仍保持正常大字。

- 是否让目光到达正确位置，让变化更好理解？
- 是否推进动作、情绪、节奏或空间关系？
- 去掉后，表达是否有损失？

固定版式里的文字漂动、边框呼吸、波形摆动多是装饰，不能代替故事和演示。技术可以用 HTML/Canvas/Python，但观感不能只像翻网页幻灯片。

## 画面与风格

- 真实主体是主要内容；桌面、手部、屏幕关系可能是可信度来源。
- 标题、字幕、指示线各司其职，避免同一句话重复三个位置。
- 留给画面讲述的空间，不每秒都用大标题/解释卡遮主体。
- 不固定黑底黄字、统一卡片尺寸；依据素材和调性重新构图。
- 合成元素的光线、动作、材质和声音一致；少一个不协调元素好过堆廉价特效。
- 末尾截图口令可稳定停留，这是操作需求，不代表正文也做成静态卡片。

## 下次具体探索

为下一条素材形成一个明显不同于本次固定页面版式的方案，说明它怎样服务钩子或功能反转。可用新的叙事、镜头或原创素材，不限定一种技术。

正常速度看代表片段，确认创意与产品有关、确实改善观感，再扩大制作。无需为了“模型实力”加身份片头或无关炫技素材。

## 审美自检

静音看：画面是否能讲清一次变化？遮住标题看：仍在讲故事，还是只剩固定页面？正常速度看：是否重复、读字疲劳、低质合成，或声音与动作各走各的？

问题仍在时，如实标记风格缺口，不能因可解码就称为优秀标杆。

## 2026-10-15 新试验：文字回应语义

自动续火花参考了用户提供的文字 MV：字的形态与“忘记 / 持续运行”动作对应，字可以压扁、熄灭、弹回或环绕设备，而不是永远浮在同一张卡片里。留出稳定真人段落与截图段落，让运动有疏密变化。只观察到画面时，不把曲名/标题描述当成已试听的踩点证据。

本片用电脑合盖、服务器继续亮灯说明条件；真实产品UI仍由实际录屏提供。最终用户给72分，认为像素动画有进步但与优质游戏实况仍有差距，见[案例](cases/2026-10-15-xuhuohua.md)，不是通用优胜模板。

## 20 分失败后的具体修正

自动续火花首版 20 分，用户明确反对小字、难看的变形字和过多云端讲解。正文普通中文字幕首先保证可读，创意放到动作、镜头、反应和声音；不要让字效损害理解。用户给出精选表情文件夹时先看并使用其中原素材，不能用新生成角色替代其明确选择。

营销主线按最新用户重点安排。用户确认已实测功能时，不因演示截屏暂未注册就宣布功能失败，也不把制作核验的“未实测/兼容状态”清单塞进片内；后台报告应保留事实边界，源 UI 不造假。名称以用户纠正后的“捞鱼、豆包”为准，不能照抄错误语音转写。

截图式Agent指令可直接作为输入，片尾明确“截图给豆包”、保证稳定可读即可。用户提供的截图只支持其中可见步骤，不能顺带宣布安装和运行全链路已成功。该v2最终获72分，具体动画不足见下节。

## 72分反馈：表情与像素场景

自动续火花最终72分，用户明确喜欢微信精选表情与封面；同时指出“表情包就上下机械动动”很蠢，像素动画虽进步却远低于优质游戏实况观感。选对素材和动作表现是两项独立工作。

表情按当时情绪设计动作起因、预备、反应、停顿与退场；探头/回看、蓄力/冲入/落地要有不同节奏，避免所有PNG全程正弦浮动。适合静止的地方就停住。新动作帧需保持用户原角色，不用无关替代物。

像素段落下次先试4–6秒完整场景：有可读空间、角色目标、交互触发、连续动作和结果反馈；按需要加前后景、视差或镜头跟随。不能只靠图标漂移、闪灯和文字卡冒称游戏实况级。示意与实际功能证据分清，不能伪造软件结果。先正常速度审一个代表段落，再用于全片。这些是下一次试验，不是已有优秀成果。

封面得到明确认可；真人、大字层级、火苗/时钟意象和横竖独立构图可沿用为该系列经验，不固化所有产品的配色或版式。
